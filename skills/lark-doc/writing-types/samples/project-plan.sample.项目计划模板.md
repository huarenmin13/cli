# 项目计划模板集

使用方式:根据用户场景从以下 5 套模板中**选一套最匹配的**,保留标题层级、表格列名和占位标记,用用户信息替换 `[占位]`。未涉及的章节可整节删除或标注"暂不展开"。

通用占位:`[项目名称]` / `[背景简述]` / `[总目标]` / `[关键指标]` / `[负责人]` / `[部门]` / `[第 N 周]` / `[T+N]` / `[预算范围]`。

---

## 模板 A · 执行推进型

适用:业务落地、项目启动、专项执行、内部推进。

风格:直接、务实、动作导向,多表格、少套话。

### 1. 项目目标(3-5 条关键结果)

- 总目标:`[一句话目标]`
- 关键结果 1:`[可衡量指标]`
- 关键结果 2:`[可衡量指标]`
- 关键结果 3:`[可衡量指标]`

### 2. 阶段划分与关键路径

| 阶段 | 起止时间 | 关键任务 | 产出物 | 责任人 | 前置依赖 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 启动 | [第 1 周] | 目标对齐、范围确认 | 项目章程 / 范围文档 | [项目经理] | - |
| 筹备 | [第 2 周] | 资源与方案对齐 | 方案稿 / 预算表 | [主责部门] | 启动完成 |
| 执行 | [第 3-6 周] | 关键动作推进 | 阶段性产出 | [执行组] | 筹备完成 |
| 验收 | [第 7 周] | 结果检查与复盘 | 验收报告 / 复盘纪要 | [验收方] | 执行完成 |

### 3. 关键任务与优先级

使用 P0/P1/P2 标注,只留 P0 1-3 项、P1 3-5 项,P2 往后作为"可延后项":

| 编号 | 任务 | 动作 | 产出物 | 优先级 | 责任人 | 节点 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | [任务名] | [具体动作] | [产出物] | P0 | [责任人] | [时间] |
| 2 | [任务名] | [具体动作] | [产出物] | P1 | [责任人] | [时间] |
| 3 | [任务名] | [具体动作] | [产出物] | P1 | [责任人] | [时间] |

### 4. 里程碑与检查节点

| 里程碑 | 验收标准 | 交付物 | 时间 | 确认人 |
| :--- | :--- | :--- | :--- | :--- |
| M1 目标确认 | 目标 / 范围 / 指标签字 | 目标确认稿 | [时间] | [确认人] |
| M2 方案完成 | 方案稿 + 预算可执行 | 方案稿 / 预算表 | [时间] | [确认人] |

| :--- | :--- | :--- | :--- | :--- | :--- |

| :--- | :--- | :--- | :--- | :--- | :--- |

| 系统 / 权限 | [说明] | [现状] | [缺口] | [需谁拍板] | [时间] |

## 模板 B · 汇报请示型

适用:向上汇报、申请资源、争取支持、方案汇报。

风格:结论前置、重点明确、判断清晰;**不出现未经确认的金额和承诺性数据**。

### 1. 汇报摘要(先给结论,建议用表格或 3 段文字)

| 要点 | 结论 | 需要的支持 |
| :--- | :--- | :--- |
| 要做什么 | [一句话目标] | [需要谁 + 什么决策 + 时间] |
| 关键路径 | [3 个关键阶段] | [需要资源/人力/预算] |
| 风险与建议 | [1-3 个高风险 + 应对] | [需要拍板的事项] |

### 2. 项目背景与当前问题(2-3 段)

- 背景:`[2-3 句话说明为什么做这件事]`
- 当前问题:`[1-3 个关键问题,优先用数据或事实,不要空泛判断]`

### 3. 核心目标与关键结果(3-5 条)

- 目标 1:`[目标 + 指标]`
- 目标 2:`[目标 + 指标]`
- 目标 3:`[目标 + 指标]`

### 4. 推进思路(1 段话 + 一张阶段表)

| 阶段 | 关键动作 | 时间 | 责任人 |
| :--- | :--- | :--- | :--- |
| 启动 | [动作] | [时间] | [责任人] |
| 方案 | [动作] | [时间] | [责任人] |
| 执行 | [动作] | [时间] | [责任人] |
| 验收 | [动作] | [时间] | [责任人] |

### 5. 关键举措(3-5 项,每项 ≤3 行)

- 举措 1:`[做什么 + 产出 + 责任人]`
- 举措 2:`[做什么 + 产出 + 责任人]`
- 举措 3:`[做什么 + 产出 + 责任人]`

### 6. 所需支持(这是汇报的核心决策点,必须具体)

| 支持项 | 需要谁 | 做什么决策 | 最晚时间 | 目前状态 |
| :--- | :--- | :--- | :--- | :--- |

| [预算] | [角色] | [决策内容] | [时间] | [当前状态] |
| [权限/跨部门协调] | [角色] | [决策内容] | [时间] | [当前状态] |

### 7. 风险提示(2-4 条,用表格)

| 风险 | 影响 | 应对动作 | 责任人 |
| :--- | :--- | :--- | :--- |
| [风险 1] | [影响] | [动作] | [责任人] |
| [风险 2] | [影响] | [动作] | [责任人] |

### 8. 预期结果(1-2 段,≤3 条结论)

### 4. 时间节奏与协同方式

- 例会节奏:`[频率 / 时长 / 产出]`

## 通用表格列名规范(所有模板统一使用,便于裁剪与复用)

**排期/里程碑表**:阶段 / 关键任务 / 产出物 / 责任人 / 时间节点 / 依赖
**责任分工表**:事项 / 主责方 / 协同方 / 支持方 / 交付物 / 节点
**风险表**:风险 / 影响 / 预警信号 / 应对动作 / 责任人
**资源/预算表**:资源项 / 需求 / 现状 / 缺口 / 需决策 / 时间
**协同接口表**:模块 / 主责方 / 协同方 / 接口人 / 交付物 / 节点 / 升级路径
**任务优先级表**:编号 / 任务 / 动作 / 产出物 / 优先级 / 责任人 / 节点
**汇报摘要表**:要点 / 结论 / 需要的支持

> 注意:如果用户场景只需要局部模块(只要风险 / 只要排期 / 只要分工),不要强行输出完整模板,只取用对应表格模块即可。
