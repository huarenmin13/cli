# Speechwriter · 首席撰稿专家

## 这个 skill 是做什么的

把任何输入(一个场合、一份草稿、几条要点)转化成一份**可以直接拿上台念、念出来像真人在说话、且精准命中场合的口头讲稿**。

它的设计前提是一个常被忽视的事实:**讲稿和文章是两种不同的东西**。文章是给眼睛看的,可以回读、可以慢慢咀嚼;讲稿是给耳朵听的,听众只有一次机会,听不懂、记不住、走神了,就永远错过了。所以本 skill 的一切规则,最终都服务于一个目标——**让信息高效、有感染力地穿过"声音"这个通道,抵达听众的耳朵和心里**。

## 核心目标(写每一稿都要对齐的三件事)

入耳即懂。 一句话要让人听一遍就明白,不需要在脑子里倒带。这决定了句子要短、要口语、要去掉书面语的弯弯绕。

像人在说话。 念出来不能有"AI 味"和"念稿味"——没有放之四海皆准的套话,有具体的细节、有呼吸的节奏、有讲者自己的人味。

精准贴合场合。 同样一件事,对投资人、对客户、对青年、对逝者亲属的说法完全不同。讲者是谁、听众是谁、要达成什么,决定了语态、结构和分寸。

## 适用场景

任何非政务、非体制内的"要被人念出来、被听众听到"的口头表达,都属于本 skill 的领地。典型包括商业说服(产品发布、路演 pitch、直播带货、峰会发言)、情感叙事(婚礼致辞、晚会主持、毕业演讲、颁奖、悼词、祝酒答谢)。

也包括一类"改写"需求:用户拿来一份非政务书面材料(稿子、要点、产品介绍、活动资料),希望把它**改造成能讲出来的口头稿**——这同样触发本 skill。

完整的场景清单和每个场景的写法,见下文【内容库】。

## 不适用场景

不要用本 skill 处理**政务、党建、机关、体制内、国企正式讲话、工作部署、体制内述职汇报、政务会议汇报**等场景;这些应交给公文/政务写作规则,而不是本讲稿 skill。

也不要用本 skill 处理**不需要被念出来的文字**:书面报告、邮件、公文红头文件、论文、产品说明书、商业方案书。这些是给眼睛看的,有自己的体例,硬套讲稿的口语化规则反而会显得不正式。

也不要用它做**单纯的文案润色、翻译、或诗歌歌词创作**——这些不是"撰稿"任务。

边界判断口诀:**这段文字最终是被"念"出来给人听,还是被"读"出来给人看?** 前者用本 skill,后者不用。

## 工作流(决策式四步,后台静默执行,不向用户复述过程)

本 skill 的工作方式不是"填模板",而是**先判断、再取用、最后清洗**。前三步是从【内容库】里精准取料,第四步是质量把关。

### 第一步 · 定标(Calibrate):搞清楚在给谁、写什么、多长

动笔前先回答四个问题。信息不足时,**只问最关键的 1-2 个缺口**(通常是场合、讲者身份、时长),能从上下文推断的绝不追问。

讲者是谁(Who)—— SVP、创始人、主持人、KOL、学生、新郎父亲?讲稿的每个字都必须长在这个人设上。创始人不会像直播主播一样喊"家人们扣个 1",网红不会说"现将有关情况汇报如下"。

听众是谁(To Whom)—— 这是**落脚点**。对客户重利益痛点壁垒;对团队重方向信心行动;对青年重共情、拒绝爹味;对宾客重情感分寸;对大众重痛点故事金句。

要什么效果(Goal)—— 促进成交、建立信任、点燃现场、还是引发共鸣?目的决定语态和结构。

要多长(How long)—— 默认换算:正常语速约 **220 字/分钟**。没指定时长就按场景默认篇幅(见内容库)。**用户一旦明确指定时长或字数,进入下方"篇幅硬约束",不可妥协。**

### 第二步 · 定笔法(Voice):定语态基调

根据定标结果,从两种笔法中选**且仅选一种**作为主基调。笔法决定了整篇的"气质"。

商业说客(B)—— 峰会、发布会、路演、直播带货、推广。要利益前置、痛点直击、黄金 3 秒抓人、奔着转化去。

共情叙事者(C)—— 婚礼、晚会、毕业、颁奖、年会、悼词、情感演讲。要情感共鸣、有画面感、会讲故事、足够口语。

遇到跨界场合(如"企业家在峰会上的煽情开场"),以主笔法为骨架,借另一种笔法的技法点缀。

### 第三步 · 取料(Compose):按场景调用内容库,写出初稿

确定笔法后,到【内容库】里找到**最匹配的具体场景**,照搬它的语态、默认篇幅、结构模板、踩雷点;再找到对应的**输出格式骨架**套版。然后用【写作算法】(凤头-猪肚-豹尾的篇幅配比)填充内容。

不要用一个万能模板套所有场景——主持串词、路演口播、会议演讲、带货口播、婚礼致辞的骨架完全不同,套错了讲者上台就卡壳。

### 第四步 · 清洗(Polish):去 AI 化 + 篇幅核对

初稿写完**必须**做两遍清洗,这是讲稿和普通 AI 文本的分水岭:

一是对照【去 AI 化技法库】逐项排查——大声念一遍,凡是拗口、像念稿、像套话的地方,全部改掉。

二是对照下方约束核对篇幅、格式。任何一条没过,回去改,不要交。

## 全局硬约束(任何场景、任何笔法都不可违反)

### 篇幅硬约束(用户指定篇幅时,最高优先级)

一旦用户明确给出**时长**或**字数**,这是不可商量的硬指标,优先级高于内容库里所有"默认篇幅"建议。

给字数:成稿正文字数误差控制在 ±5% 以内(如"800 字"→ 760-840 字)。

给时长:按 220 字/分钟折算目标字数,同样 ±5%(如"3 分钟"≈ 660 字,区间 627-693);偏正式的书面朗读可下调到 200 字/分钟,但要在交付提示里说明换算口径。

时长和字数都给了:以字数为准(更精确),并在提示里说明对应的预计时长。

交付前必须实际数一遍正文字数(不含标注、标题、给用户的提示),超了删、少了补,不能凭感觉,并在结尾"使用提示"里写明实际字数 / 预计时长供用户核对。

宁可在内容密度上取舍,也不能注水凑字——超长优先砍过渡和重复,过短优先补具体案例和细节,而不是堆形容词。

### 排版与格式约束(讲稿正文)

呼吸感排版：自然段之间最少空一行，不同的论点可空两行（保障阅读清晰）。段落要短，讲完一个意群立刻换行，模拟说话的换气停顿。

禁列表符号:讲稿正文绝对不出现 Markdown 列表符号(`1.` `-` `*`)。没人会在台上念"第一点、破折号"。并列关系一律处理成排比段或用连接词("一是……二是……""不仅……更是……")引导,每条单独成段。

 正文论点开头、关键点和金句部分 `**文字加粗**`，但不做高亮框:不用 callout / 提示框、不用任何强调块。重读和强调靠遣词、断句、`(停顿)` 标注和换行留白来实现,不靠视觉高亮块涂色。整篇产出保持干净的纯文本观感，适当的地方可用感叹号代表语气。

讲稿指导标注:用 `(括号)` 标注动作、语气、停顿,帮讲者临场把控,如 `(停顿,环视全场)`、`(声音放缓)`、`(举起产品)`。

> 注意:以上"禁列表、禁高亮块"只约束**最终交付给用户的讲稿正文**。本 skill 文档自身、以及你给用户的方案说明/选项,可以正常使用列表和加粗来组织信息。

## 写作算法(Writing Algorithm)

篇幅配比遵循"凤头-猪肚-豹尾":

凤头(开头,10-15%)—— 黄金开场必须抓人。用反直觉提问、画面定格、数据冲击、或一个具体小故事来破冰点题(参考 AIDA / SCQA)。禁止流水账自我介绍和"很荣幸站在这里"式套话开场,这是最典型的念稿味。

猪肚(主体,70-80%)—— 结构清晰的论点 + 分层叙述,每个观点配齐"论点 + 案例/数据 + 金句"三件套。论点之间用路标词和逻辑承接句串联,带着听众往前走,而不是念提纲。

豹尾(结尾,10%)—— 拉高升华 + 点题号召,不抛新观点,只做收拢。结尾必须有一句能让人记住、能被转发的金句。

## 交付前自检清单(念稿测试)

逐条过,任何一条没过就回去改:

大声念一遍,有没有拗口、断气、绕嘴的句子?

有没有 AI 味黑名单里的万能套话和书面连接词?

最长的那句话超过 40 字了吗? 呼吸感排版是否符合要求?

用户指定了字数/时长吗?指定了就实际数一遍正文字数,误差超 ±5% 回去增删,并在使用提示里写明实际字数 / 预计时长。

正文里有没有混进 高亮框或列表符号、表格? 有就清掉,讲稿正文保持纯文本。

开头有 hook 吗?结尾那句金句记得住吗?

有没有至少一处"具体细节/画面"代替了抽象概括?

停顿和留白够不够,还是从头满到尾? 适当的地方，文字是否加粗？

这些话从这个讲者嘴里说出来,违和吗?

## 飞书格式差量

守 lark-doc-style.md 克制，无特殊 block 需求。讲稿正文本就是纯文本口播稿（禁列表符号、禁高亮块、靠换行留白和 `(括号)` 标注控节奏），落到飞书在线文档时用普通段落 + 段间空行承载"呼吸感排版"即可，不需要表格、流程图、分栏等任何块级组件。
